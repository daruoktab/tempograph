01 · Causal life-event graph

80 life events and 83 causal links, as a graph you can pull apart

Before any conversation exists, the generator writes a dated event DAG: each event can list the earlier events that caused it (caused_by). Sessions are then written around those events, so the benchmark has real cause-and-effect to ask about. This is the actual user_events.json from the repo — drag nodes, click one to trace its causes and effects, or press play to watch January–April unfold.

Why it matters

Take E1 → E9 → E13: the big campaign (E1) triggers a creative block (E9), which feeds into finishing the first concept draft (E13, also helped by E12). Multi-hop evaluation queries ask for exactly this kind of cross-session chain — not one similar chunk.

02 · Bi-temporal conversational memory

Don’t overwrite old facts — give every fact a validity window

Each extracted_fact carries valid_at and invalid_at. When a newer fact supersedes an older one, the old row isn’t deleted; it just gets an end date. Drag the cursor to ask the memory a question as of any day. Facts and dates below come from the example dataset (Aisha’s coffee-brand collaboration).

      06 · Reproducible experiments
      
One --setup env contract swaps providers, embeddings and retrieval mode

      
Model choice is decoupled from ingestion and evaluation scripts. Pick a stack and copy the generated .env and commands. Evaluation reports hit rate / MRR on expected sessions, retrieval latency per query, and an optional LLM-judged context-sufficiency score.
